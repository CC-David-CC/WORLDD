# Threat model

## Protected assets

Authority private keys; encryption keys; canonical resource identity and state; effective
permissions; aggregate budgets; audit receipts; current revocation/epoch information;
private plaintext; and the ability to decide whether a network process is started.

## Adversaries for local acceptance

Malformed object producer; corrupted/torn storage; stale snapshot restorer; malicious or
compromised capability subject; arbitrary local agent code; concurrent requests; replaying
client; forged parent or signer; malicious provider result; and untrusted plugin code.
A later network peer is not yet present. Test these local adversaries with generated bytes
and dummy processes, not a live model whose behavior happens to be cooperative.

## Trusted computing base

For a target LOCAL_READY profile: host kernel and selected isolation mechanisms, immutable
runtime/dependency bundle, minimal broker/verifier/custodian, trusted policy/requirements
roots, entropy source, and a rollback anchor whose trust/lifecycle is explicitly specified.
A compromised host administrator/kernel can replace the verifier, inspect ordinary process
memory or alter permissions. This package does not claim resistance to that adversary.
Measured hashes alone do not remove that trust assumption.

## Current native launcher boundary

The C launcher closes inherited non-stdio descriptors, rejects socket stdio, removes
effective Linux capabilities, uses no-new-privileges, checks the syscall ABI and denies
socket creation/use plus listed bypass interfaces. It is installed before Python imports.
A child inherits the filter. Unix sockets are also denied; trusted local fixture IPC uses
pipes and files.

This is NOT a full sandbox. Regular files, FIFOs, inherited stdio pipes, shared directories,
local helper processes, unusual device APIs, writable executables, library injection and a
host-controlled filesystem can form alternate communication or authority channels. The
full P04 acceptance profile must provide an isolated fixture mount tree, device restrictions,
UID/process separation, no unapproved inherited FDs and a reviewed syscall/access profile.
No claim that “all communication is impossible” follows from eight passing socket probes.

`unshare -n` was unavailable here. P04 must test namespace isolation on the actual target
host or implement an equivalently justified target boundary. A namespace alone is also not
sufficient: it can still have loopback, inherited descriptors or local proxies.

## Explicit limits

Public key IDs are key identities, not proof of a human's identity. Hashes prove content
consistency under cryptographic assumptions, not authorship or legal title. Fixture report
keys are not user root keys. AEAD protects ciphertext integrity/confidentiality under its
assumptions, not plaintext already copied into logs, swap, crash dumps or model prompts.

The object store exposes plaintext-derived IDs and metadata. Dictionary guesses against
low-entropy content IDs are possible. Production private replication must not expose them
without a deliberate privacy decision. Equal plaintext need not yield equal ciphertext.

Offline revocation cannot instantly reach a disconnected independent node. This phase only
requires immediate behavior in one authoritative local serialization domain. The network
phase needs explicit freshness, leases or an authority protocol and cannot inherit global
revocation by wishful thinking.

Recovery does not make previous signatures cryptographically invalid. It changes current
authority/epochs while retaining the ability to verify historical evidence.

## Residual risk record

For every acceptance gate, record assumptions, adversary, platform, test corpus, observed
result and unsupported cases. A failure to establish an assumption is PENDING/UNSUPPORTED,
not PASS. Never aggregate a failing mandatory security property into an average score.
