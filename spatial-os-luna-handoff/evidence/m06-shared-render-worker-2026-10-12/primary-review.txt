M06 shared worldd rendering client and world-owned captures

Production behavior
RenderWorker can own a legacy compositor or retain a private shared channel.
Shared mode retains the compositor process handle but cannot terminate that process.
worldd validates inherited channel descriptors and requires sealed native configuration.
The shared client authenticates replies, checks request identity, rejects reply descriptors,
and closes only its channel after uncertain transport failure.
The scheduler and before-send authority checks remain active during exchange.

Each world creates private capture files through its retained captures directory descriptor.
The compositor receives one writable file descriptor for a capture command.
It validates an empty regular file, private mode, owner, link count, and writable access.
The compositor does not choose or return a shared capture path.
The world checks output length and supplies its own path after the reply.
Failed captures remove the unacknowledged file. Legacy capture behavior remains unchanged.
The descriptor requirement is an explicit extension of the new private presentation protocol.
