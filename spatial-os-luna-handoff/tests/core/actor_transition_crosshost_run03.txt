Run03 trusted semantic orchestration

Source-reviewed implementation. Runtime qualification remains UNRUN.
This fixture does not qualify native presentation, input retirement, or M06.
It adds no production library API and makes no headless retirement claim.

Deploy the complete run03 bundle to the SAME absolute path on sb16 and sb16-2.
Use an unprivileged dflanag3 account. Keep normal login and recovery routes open.
The launcher accepts a profile and a NEW absolute evidence directory.

Provisioning sequence

Create a private dedicated issuer directory outside Git on the driver host.
Generate distinct Ed25519 owner, actor, TLS and participant keys using OpenSSL.
Use existing WorldIdentityFixture/ClientFixture/TlsFixture issuer methods.
Initialize the real issuer with identityd --init --owner-public.
Manually approve the shared actor and two source-only actors through issuer proofs.
No existing issuer database or actor identity is modified.
All created issuer rows belong to the isolated recorded identity.db.
No participant-unregister command is needed to remove another issuer's rows.

Record each remote /tmp/spatial-m06-run03-TOKEN-HOST path before sending create.
Each new private root has an owner marker binding token, UID, device and inode.
Use stopped worldd management world.info to initialize each real state/world.db.
Create saved-room using trusted production world.create management.
Read each actual world ID from production protobuf replies, never caller labels.
Register one real issuer AuthorityParticipant for each persisted WORLD domain.
Reuse WorldIdentityFixture.configure_participant; rewrite only material paths per host.
Create authority directories and install persistent roots through worldd --init-authority.
Grant the shared actor WORLD_ENTER and WORLD_NAVIGATE in both worlds.
Grant each source-only actor those rights only in its source world.
Private denial therefore exercises real persisted policy and real actor credentials.
Admission has no static actor/grant override.

Launch one worldd on each host through a bounded private tmux owner.
Each owner binds a real host address and passes its inherited listener to worldd.
It retains the production management pipe behind a mode-0700 local Unix socket.
SSH invokes only trusted setup management; actor actions never use that socket.
Mutual TLS uses per-world server certificates, DNS SAN identity and explicit client trust.
The production issuer client pins issuer ID and public key.
An unlistening bound socket reserves each unavailable endpoint until cleanup.
No listener is killed or repurposed to construct an outage.

Record exact world/owner PID, /proc start ticks, command, executable hash and port.
Independently map each live listener inode to its worldd PID and durable state path.
Require the observed owner to match the launched worldd.
Read saved actor rows using the read-only SQLite protobuf witness.
The two host-specific roots and world IDs must differ.

Seed shared and source-only actor contexts before constructing the six-case plan.
The crosshost C++ probe's SeedContext mode authenticates via ActorSessionClient.
It checks the real inspection and calls checked depart to persist the context.
The independent witness verifies saved-room, pose and world ID afterward.
The six coordinator cases do not use SeedContext or an explicit transition spawn.
They exercise round-trip, private denial and unavailable destination in both directions.
Failure follow-up performs authorized zero-axis navigation and stop through C++.
The existing harness requires source inspection and unchanged durable entity/revision.
The same shared actor resumes distinct saved contexts on both authoritative worlds.
The denial cases use real source-only actors, since the shared actor can enter both worlds.

Cleanup and recovery

Cleanup runs after success, setup error, harness failure, cancellation or timeout.
Each run first checks slow-owner shutdown: one stop request is sent, then the exact owner is polled.
The evidence directory records cleanup-transport-regression.txt after this check passes.
The owner has a 1200-second lifetime. The controller has separate cleanup deadlines.
Before terminating/removing resources, retain coherent database backups and command logs.
Backups read authoritative databases through SQLite mode=ro and online backup.
They do not edit semantic state. They exclude private keys and actor TLS configs.
Evidence directories are private and contain real issuer rows and credentials.
Never add runtime evidence databases or credentials to Git.

Closing the owned worldd management pipe requests production orderly shutdown.
If shutdown expires, signal only a retained pidfd after PID/start/executable/command checks.
Do not restart a stopped authority or claim its issuer generation is retired.
Forced shutdown is recorded as a nonzero worldd exit and a cleanup qualification failure.
Before removal, verify the token, UID, device/inode, absence of live owners and link/mount safety.
If a launch lacks a PID record, scan exact state-dir references and retain any ambiguous process.
Unknown or changed ownership leaves resources in place and makes cleanup fail.
Snapshot or SSH failure also retains resources for recovery.
Preserve the original failing logs; do not retry with altered authority rules.

cleanup.json lists retained roots and the exact helper stop argv on incomplete cleanup.
Run that stop command only on its recorded host, with the bundle's Python environment.
Then run helper snapshot and save stdout before helper remove.
The ownership token and paths are recorded in ownership.json.
Issuer snapshots and row inventories precede owned issuer shutdown/removal.
No shared issuer rows, unrelated PID, path, listener, tmux session or service are removed.
