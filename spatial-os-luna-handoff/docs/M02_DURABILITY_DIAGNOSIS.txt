M02 durability diagnosis: bounded write interference

Status: planned experiment. This is not milestone qualification.

The captured sb16 failure spent 1.433958 seconds in two successful fdatasync calls.
The client deadline was 700 milliseconds. The issuer handles database work in its TLS loop.
The older approval and revocation failures lack equivalent issuer traces.

Hypothesis
Concurrent filesystem writeback can stall issuer commits and unrelated participant requests.
Start pressure only after fixture setup, at the selected operation boundary.
Compare baseline, pressure, and recovery with the same binaries and original test method.

Recommendation
Retain the existing five-second production client default.
Keep short deadlines for deliberate timeout tests.
Propose normal-operation test configuration separately. Do not silently change the 700 ms fixture.
Measure and contain competing workspace or build writes.
Investigate transport responsiveness separately from durable commit latency.
A database worker can preserve transport progress but cannot make a pending durable commit complete sooner.
Do not authorize actions from stale or uncommitted authority state while database work is pending.
The original three historical timeout causes remain individually unproven.
