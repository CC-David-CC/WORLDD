Minimal observer design to investigate

Use a separate test-only EventCallback observer module in the XACE baseline build.
No mutable DeviceEventCallback context or enqueue/delivery pairing is required for this XI2-only design.
DeviceEventCallback may support optional held-state diagnostics. It must not determine accepted-event identity.

Pinned xorgproto commit 67469711055522b8adb2d795b01e7ba98cb8816c defines xXIDeviceEvent in include/X11/extensions/XI2proto.h:960-984.
It contains GenericEvent type/extension/length, evtype, deviceid, sourceid, event XID, detail, time, and flags.
Pinned server dix/eventconvert.c eventToDeviceEvent():657-694 copies deviceid/sourceid from the native DeviceEvent.
dix/events.c FixUpEventFromWindow():2691 dispatches XI2 target/coordinate fixup before event output.
WriteEventsToClient() invokes EventCallback before client byte swapping (:6133 onwards).
Thus the observer receives native-order XI2 bytes even for a swapped client.
These fields identify the peer master device and originating slave without a DeviceEventCallback side channel.

At the callback require count == 1 and an exact unsynthetic GenericEvent type.
Require the live XInput extension opcode and XI_ButtonPress; reject raw, core, focus, and unrelated event types.
Validate the bounded 32 + 4*length size before reading xXIDeviceEvent fields beyond the generic header.
Require at least sizeof(xXIDeviceEvent), valid mask lengths, and a consistent variable payload size.
Check the recipient's authenticated application label and pinned client lifetime, not its numeric index alone.
Check event XID plus pinned window lifetime/generation and deviceid/sourceid against the prearmed peer hierarchy.
Resolve pinned old devices only while live. Snapshot actual old master/slave key->down and button->down arrays.
Include available native focus/grab state separately. Do not read SeatRec or world held-state as the release oracle.
Freeze the snapshot at this first qualifying outgoing press. Later peer events must not overwrite it.
Record monotonic observer ordinals; equal millisecond timestamps do not establish order.
Reject unrelated, duplicate, replayed, or synthetic SendEvent events.

This is an output-attempt observation before WriteToClient, not proof of receipt by itself.
Require an independent XI2 probe receipt of that same first peer press on the surviving popup.
Extend the probe's fixture record with sourceid, time, synthetic flag, and ordering data needed for correlation.
Match both first qualifying records by recipient/target/device/source/type/detail and bounded arm interval.
Reject ambiguous or missing correlation. Do not match timestamps alone or accept a later successful press.
Current native/xprobe.c XI2 JSON reports deviceid but omits sourceid/time.
Current WorldApplicationControlTests.probe() launches without --xi2 and requires xi2 == false.
A new ordered-state selector must explicitly opt into --xi2 and assert XI2 readiness.
Preserve existing core-mode destroy and reacquisition selectors without changing their expectations.

Pin identities before destruction through privileged XIGetClientPointer and XIQueryDevice hierarchy data.
Precondition each actor through ordinary control of the same application, then release and restore the old controller.
This permits pinning both actor master/slave sets without granting clients enumeration authority.
Require native held-key and held-button positive observations before arming the destroy trigger.
Destroy the main window, submit peer input before waiting for cancellation, and capture the first accepted peer press.
BUSY is not acceptance. A later successful retry still needs the first successful native-event record.
The immutable snapshot must show all old key/button state clear before the peer event is emitted.
A later snapshot, logical clearing, or peer progress cannot satisfy the invariant.
This proves native server state ordering. It does not prove that a destroyed window received release events.

Data authority and explicit missing contract

Existing callbacks suffice for observation points. No server-core patch appears necessary from source inspection.
Existing XI queries can provide device identities/current state, but cannot return an atomic historical delivery snapshot.
Existing SPATIAL-INPUT status cannot express this independent observation or its event ordinal.
Do not invent an implemented observer operation or silently extend production status semantics.
A bounded test-only observation record needs explicit fixture-contract review before implementation.
Prefer a supervisor-owned inherited descriptor and framed Protocol Buffer records over a new ordinary-client X operation.
The descriptor, arming data, schema, bounded buffering, and failure behavior would be NEW fixture interfaces.
They must be recorded explicitly. Existing security Bootstrap contains only protocol_version and supervisor_cookie.
Do not add fields or flags without review. No new wire API is implemented by this note.
Allow observer access only in an explicitly enabled qualification build/session. Keep it unavailable to confined clients.
Record no secrets. Exhausted output, truncated records, missing snapshots, or disconnects must fail qualification.

Required negative controls and uncertainties

- Retain one native old key while clearing logical bookkeeping; successful peer input must still fail the witness.
- Independently retain one native old button with clear logical bookkeeping; the witness must fail again.
- Remove the snapshot, substitute fallback application devices, swap actor identities, or reuse a device ID; reject each case.
- Exercise frozen input so enqueue callbacks cannot be mistaken for delivered peer input.
- Require ordinary-client observation/configuration attempts to fail without exposing device metadata.
Use a test-only controlled omission of native release, not a fabricated observer record, for held-state controls.
No such fault point exists yet. It requires a separately reviewed, qualification-only mechanism.
