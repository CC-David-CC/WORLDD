## Corrected oracle

The affected regression explicitly asks the supervisor to stop.
ProcessScope::request_stop() writes cgroup.kill and sends SIGKILL to its child.
OWNED_SCOPES_STOPPED proves checked process and native-scope cleanup.
It does not prove successful child exit or reconciliation of external Git effects.

BrokerCopyCleanupParticipant::pre_prune() preserves journal evidence after unsuccessful child exit.
Keep its child_exited_successfully() guard.
AuthorityLaunch::prepare() uses ProcessScope::prepare() without retained-scope mode.
ProcessScope::complete_stop() therefore removes this fixture's drained outer scope even when the callback returns false.
The bound active git_worker_parent row can refer to that exact missing root.
Retained production scopes use a different lifetime rule.
The earlier read-only diagnosis incorrectly described this caller's outer scope as preserved.

The immediate empty-table assertion conflated supervisor cleanup with successful broker exit.
This explicit oracle correction requires exact recovery evidence first, then eventual empty active and retained tables.
It changes this added regression only.
No production code, locked acceptance test, acceptance lock, timeout, or normative contract changes.
All 14 test methods remain in the regression inventory.

The test records the running parent before forced stop.
It checks actual root and worker device/inode values against durable identities.
After stop, it checks the same root tuple, path, and complete serialized worker identity.
It requires one bound active row, no retained rows, and absent physical root and worker directories.
The independent native client must survive the forced stop.

A fresh production supervisor then starts workspaced against the same execution directory and delegated cgroup parent.
Recovery keeps the participant, issuer, registered revision, and execution state.
It uses a new service incarnation in both binding and participant runtime configuration.
Authorization uses the participant's maximum durable activation generation, or zero when none exists.
Every existing activation must be inactive before recovery.
The exact issuer authorization row must match participant, incarnation, launch, request, and supervisor public key.
The record must also match the known issuer and registered participant identity.
An activated prior launch requires its consumed authorization and exact checked fence.
Its activation generation must equal the current maximum and its request's previous generation plus one.
A never-activated prior launch instead requires an unconsumed authorization, no fence, and a request matching the current maximum.
These are separate checked states. An empty filtered query alone does not authorize recovery.
The new launch record must bind its authorization to the new incarnation and process launch identity.
After real broker hello, startup recovery must leave both parent tables empty.
This fixture's management-only recovery must preserve activation history and leave its new authorization unconsumed.
The independent native client must also survive recovery and the second checked stop.

A failure captures parent rows, activation metadata, consistent SQLite snapshots, and supervisor logs before fixture teardown.
