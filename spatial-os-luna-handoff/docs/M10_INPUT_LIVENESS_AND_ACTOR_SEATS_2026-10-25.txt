M10 actor seats, input liveness, and overload contract
Status: implementation in progress. M10 remains unqualified.

This contract change combines the M10 movement-liveness and native-input fixes.
It preserves the actor authorization boundary and the existing 250 ms motion expiry.
It does not change any locked acceptance assertion.

Actor seat and application lease

Each authenticated actor session owns one server-created native input seat.
The seat identity never comes from an application or actor request.
The seat is retired on session closure, transition, revocation, or confirmed cancellation.
The world, native router, and XLibre each compare the focused surface generation
before accepting an actor keyboard command.

One actor controls an application surface group at a time.
The actor acquires one broker control lease for that application.
The world retains a checked binding to that lease, the actor session, the application,
the compositor incarnation, the native server generation, and the focused surface generation.
The binding identifies a target. It is not permission and is never persisted.

Before each native input effect, the world checks the active actor session, the actor's
current grants, the broker's observed revocation state, the live lease, and the exact
cached target generation. The renderer and XLibre input extension check the native seat
owner, focus, and server generation again. A new key edge in the same application does
not acquire another lease or synchronize every surface. An app change, stale target,
revocation, cancellation, or uncertain result retires the seat and releases held input.

Key taps and key holds

One-shot typing uses an atomic bounded key-tap batch. The batch validates every keysym,
seat, target, and lease before injecting any edge. Each tap emits one press and one release
without waiting for another actor round trip. A batch contains at most 32 taps. A chord
contains at most eight keysyms. Invalid input rejects the whole batch with no key effect.

Gaming and modifier controls retain explicit press and release edges. Their held-key ledger
remains actor-local. A tap cannot release a held key. A release cannot introduce a new key.
Stop, source loss, cancellation, controller loss, and revocation release every held key.
Adapters choose tap or hold semantics explicitly; they never infer a long hold from a
delayed response.

Movement refresh and revocation

An already authenticated actor may refresh only its current six-axis movement intent.
The refresh carries the actor sequence and passes through the same local ActorControl,
Actors::act, token, and navigation-grant checks as other actor actions. It has no reply
and cannot invoke a renderer, broker acquisition, workspace operation, or durable action.

The world accepts a refresh only while the retained actor session, authority participant,
service incarnation, acknowledged revocation feed, and actor navigation grant remain
valid. It consumes revocation updates before applying queued refreshes. The world cancels
movement and input immediately when it consumes a matching revocation. A lost participant,
feed gap, stale incarnation, malformed refresh, or sequence failure invalidates the channel
and cancels the actor. There is no wall-clock permission grace period.

The old draft required a new participant progress receipt after every motion ingress.
This update removes that per-ingress barrier. The live, checked revocation feed remains
the authority boundary. A remote issuer or broker round trip cannot gate an already
authenticated movement refresh. The 250 ms motion-intent expiry remains unchanged.

Bounded overload behavior

The host coalesces only adjacent, not-yet-processed motion samples for the same actor,
device source, and source generation. The newest absolute axis state wins. Relative mouse
deltas are summed and carry the newest sequence and capture time. Key, button, scroll,
tap, and cancellation edges remain ordered and are never coalesced.

All actor queues and frames stay bounded. A full queue reports backpressure, retires that
capture binding, and requests checked cancellation. The implementation may not drop a
discrete edge silently. Agent text entry uses the bounded tap batch; motion uses latest
intent. High-rate proposals do not create an unbounded history.

Required focused evidence

Use the real native server and independent XI2 event witness. Delay action completion by
at least 750 ms and prove that an atomic tap creates exactly one press and one release.
Prove an explicit held key remains held until release or cancellation. Measure movement
refresh gaps during a slow native renderer command, a delayed broker authorization reply,
and another actor's authentication.
Require every observed gap to remain below 250 ms while the actor source and revocation
feed remain healthy. Revoke a navigation grant during another actor's delayed credential
check and prove movement stops. Revoke an active actor identity during that delay and
prove the independent XI2 witness sees key and button release before the 250 ms expiry.
Send at least 1000 motion samples per second and verify bounded memory, fair actor progress,
ordered discrete edges, and explicit backpressure under saturation. Repeat the combined
regressions on sb16 and sb16-2 in Debug and sanitizer builds.
