# M08 file engine foundation

This is an unqualified M08 source increment on branch `m08/foundation-1e58-base-20261016`, based on frozen M07 pin `1e58e65dec132a0a16f004ca4527034dca081f77`.

`proto/spatial/workspace/v1/cabinet.proto` defines a versioned internal request and reply schema. Paths use POSIX basename bytes. NUL, slash, empty names, dot components, and the reserved `.spatial-trash` name are rejected. Requests are limited to 1,100,000 serialized bytes. File content reads and writes are limited to 1 MiB. Browse pages are limited to 256 entries and continue with a process-local directory-stream cursor. A cursor is single use and fails if the directory changes during paging. Pages are not a directory snapshot. Basename bytes preserve non-UTF-8 POSIX names.

`FileEngine` pins a usable descriptor to the broker-authorized project directory inode, including when supplied an `O_PATH` descriptor. It resolves directories and final leaves with `openat2`. Both reject symlinks, magic links, and nested mount crossings. Browse omits foreign mount entries before inspecting their target metadata. A read first pins the leaf with `O_PATH`. It checks the regular type and generation before reopening that same inode through its own descriptor with `O_NONBLOCK`. A FIFO or device never receives a data open. It does not accept host paths.

Handles are opaque, process-local, bounded, and generation checked. Non-root handles expire after ten minutes of inactivity. The empty bootstrap root handle lasts for the engine lifetime. A constructor-supplied monotonic clock supports deterministic expiration checks. Directory identity is checked on the opened descriptor actually used by the operation. Root rename, move, and trash requests fail independently of the supplied generation. Handle capacity is reserved before mutations that create a result handle. Scoped reservations release unused entries after collisions or other failed operations. Browse cursors expire after one minute; the engine bounds them to 256. Mutations request fresh scoped authority for their exact right and the cabinet's constructor-bound opaque scope. The authorizer receives the authenticated principal from the internal request. The worldd adapter that supplies the principal and calls the broker is not integrated yet.

Implemented backend actions are browse, read, create, edit, rename, move, trash, trash inspect, restore, and permanent delete. They perform real POSIX operations. Create, rename, move, restore, and trash do not overwrite an existing destination. Trash objects remain in a workspace-local `.spatial-trash` directory. The trash handle equals the 16-byte trash operation ID. A later `trash_inspect` can recover the current generation after a lost reply. Permanent delete checks `FILE_PERMANENT_DELETE` separately. It supports regular files and empty directories. Nonempty directory deletion returns conflict and preserves the trash entry.

Edit stages bounded bytes in the target directory, then exchanges the staged and current entries atomically. It checks the displaced inode and generation. If another writer replaced the target, the engine attempts to restore the displaced entry and retains staged data under `.spatial-conflict-<operation-id>`. It reports conflict or uncertainty when it cannot prove the final state. This is not a linearizable compare-and-swap against arbitrary POSIX writers. A process holding an open descriptor can still write after the check. Move, trash, and restore verify the published object identity and regular-file content metadata. Directory operations preserve the same directory inode and generation semantics. Their uncertain responses include the operation identity for reconciliation. The engine does not claim an atomic transaction across filesystem effects. It has no durable operation journal; recovery uses operation identities and inspectable trash names where available.

The protobuf defines bounded copy job start, poll, and cancel messages with byte and entry limits, job identity, progress, digest, and explicit uncertain state. Copy execution is UNIMPLEMENTED. It must be connected through the existing broker and process-scope worker path. The actor request handler must never copy synchronously.

The file engine has no public socket or actor bypass. It is not yet wired into `ActorActionRequest`, authenticated actor session handling, broker authority adapters, cabinet geometry, room reachability, presentation revocation, locked metadata privacy, or native pixels. Availability and selection do not create a cabinet. These are pending M08 integration requirements.

Allocation or unexpected failures after an effect return `UNCERTAIN` with the operation identity. Failed operations that retain staging or recovery state also return that identity. This is process-local uncertainty reporting, not a durable operation journal. No wire schema or locked acceptance contract changed.
