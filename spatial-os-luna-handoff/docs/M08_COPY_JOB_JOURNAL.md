# M08 durable copy job journal

Status: unqualified journal increment. It adds private durable storage for the M08 copy job contract. It does not change the public actor or file-action protobuf schema.

FileOperationJournal owns SQLite access on its existing worker thread. Schema version 7 stores bounded copy-job records and one broker-wide Git-worker-parent lifecycle record. A job record binds the random job ID to its initiating operation, workspace, canonical issuer and actor IDs, registered worktree root, exact FILE_COPY right, and request digest. The broker-wide record stores RESERVED or BOUND state, the canonical broker cgroup root path and device/inode/boot identity, and the exact Git-worker-parent ProcessScope identity when bound.

Source, destination, and staging locations use byte components relative to the registered worktree root. Each location includes a device, inode, generation, and file type. The record stores approved byte and entry ceilings, typed ProcessScopeIdentity, and its boot ID. It does not store process IDs or live FileEngine handles. Private record format 1 preserves deployed 16-byte ProcessScope launch identities for legacy recovery and immutable terminal receipts. New jobs use format 2 with the current 32-byte ProcessScope identity. Validators accept only the exact version/identity-length pair; writers reject new format-1 jobs. The SQLite schema stays at version 7 because this is a private record-format change.

Progress must stay within approved ceilings and never decrease. State transitions are checked in the journal. RUNNING cancellation must first enter CANCEL_REQUESTED. Terminal records cannot change. The typed terminal receipt is validated on write and every load. FAILED is allowed only before a prepared publication result exists. Its receipt requires a known FileActionError.Code, bounded detail, and no failure code on other terminal states. A complete receipt must contain a 32-byte digest.

A prepared result records the staged output basename, device, inode, type, byte and entry counts, and digest before publication. Recovery can compare the published destination inode with this durable receipt after a crash. The prepared result may be set once and then stays immutable. A COMPLETE receipt must match it.

Created and updated Unix timestamps support bounded terminal retention. The prune API removes only old COMPLETE, CANCELLED, CONFLICT, and FAILED rows, with a bounded batch. It retains UNCERTAIN rows for explicit recovery review. Callers provide timestamps from trusted broker code.

The journal preserves recovery identity. It cannot reopen or prove a ProcessScope empty, inspect filesystem objects, stop a worker, or publish a destination. Startup binds and pins the current broker root, opens the journal, and reconciles recorded copy jobs before it enables cgroup controllers or dispatches requests. Recovery verifies the canonical root path, device, inode, boot ID, parent scope, job scope, and staging identities. It stops only exact recorded job scopes. It removes a fixed unjournaled Git-worker parent only when the exact current broker root is pinned and the parent has no processes or descendants. Unknown or populated cgroups fail closed. A stale empty broker-manager cgroup may be removed only after the same emptiness checks. The journal never relaunches a worker.

An UNCERTAIN receipt is immutable and its staging evidence remains available for explicit recovery review. Startup attempts to stop only the exact recorded same-boot worker scope, then retains the receipt and staged evidence without relaunching or publishing. A worker-scope or staging identity mismatch quarantines that worktree file engine while unrelated workspaces and applications remain available. Authenticated POLL may return the durable UNCERTAIN receipt when workspace, worktree, and principal bindings match. A reboot drains old-boot scopes; repeated startup preserves historical parent bindings while reserving a separate current generation.

A graceful restart can find the prior Git-worker parent already absent. A same-boot process crash can leave that parent and its job children below the recorded broker root. A reboot drains cgroups, so old-boot scopes are not touched. A missing generation binding quarantines an UNCERTAIN worktree. Nonterminal jobs still require a verified parent binding before startup can continue. A RESERVED row records the crash window before parent creation; recovery removes only an empty exact-name parent before clearing the reservation. A BOUND row records the parent identity and canonical root path. Recovery never follows a changed path or inode on the same boot.

The focused journal test covers migration from schema version 1 through version 7, persistence across reopen, typed record validation, broker-root reservation and binding, canonical path mismatch rejection, legal and illegal transitions, monotonic progress, terminal immutability, malformed row rejection, recovery listing, and retention behavior. This source checkpoint remains unqualified until primary review and the required M08 runtime gate.

Schema version 7 adds retained_git_worker_parents for unresolved historical generations. Retirement atomically copies the exact active binding into retained evidence and removes only the active reservation. It does not claim cleanup succeeded. Each recovery resolves the job against its own generation. UNCERTAIN rows and their parent bindings remain immutable. Independent workspaces reserve a fresh active generation. Unknown descendants in the current root still prevent resource activation.

Prepared cancellation retains the immutable prepared output identity after private stage cleanup. Recovered publication pins and syncs the destination directory before COMPLETE. Sync failure records UNCERTAIN and preserves staged evidence. Recovery timestamps never move backwards.

The resource-backed broker regression retains an actual live orphan scope, seeds terminal uncertainty while the broker is stopped, and restarts three times. Each generation verifies authenticated POLL, unchanged journal bytes, parent binding and stage marker, no original publication, independent Git status and bounded copy, and a real application completion. The old owner is retired after exact scope cleanup. Later same-boot absence quarantines only the affected worktree. Four related cases cover prepared RUNNING and CANCEL_REQUESTED cancellation, recovered publication, and destination sync failure. These cases remain UNRUN until execution on sb16 and sb16-2.

The additive private journal field `drained_process_scope` records an exact broker-observed drain. Its identity must equal `process_scope`. New jobs cannot begin with it. Once written, it cannot disappear or change. Live and recovered ProcessScope stop observers write it after identity and emptiness checks, before removing the cgroup. CopyTreeJob supplies this observer before returning a final result. Prepared publication therefore cannot precede durable worker drainage.

A same-boot missing or replaced scope without that acknowledgment yields typed UNCERTAIN and preserved staging. Recovery quarantines only the affected worktree. A previous exact acknowledgment supports cancellation or publication reconciliation after the original cgroup is gone. Old-boot drainage remains separate. Terminal UNCERTAIN rows remain immutable, so later cleanup does not append proof or rewrite their receipts.

The authority-loss request path persists its terminal receipt before UNAUTHORIZED. Failure to confirm that commit reports UNCERTAIN. Noexcept retirement paths report unconfirmed journal durability instead of silently retaining a success claim. Live progress remains a separate unimplemented contract requirement. The drain acknowledgment is not worker progress or M08 readiness evidence.
