M09 qualification target and bounded implementation
-----------------------------------------------------
The M09 milestone row in docs/MILESTONES.md:153 requires application-group
control semantics. It does not require a physical display or an Xorg binary.
No Xorg-only restriction appears in the inspected M09 contract or acceptance
lock. M14 separately requires native devices, visible session, physical input,
and cold-reboot evidence. A real patched Xvfb can exercise X server input,
resource, and process-lifetime behavior for M09. It cannot prove physical
scanout, GPU output, or device behavior.

For M09 observer qualification, the existing configured XACE path is the
intended XLibre process chain:
1. tools/m06_deployed_gate.py:1235-1257 verifies the wrapper against the pinned
   Xvfb build receipt. At 1887-1889 it sets SPATIAL_TEST_XSERVER to that wrapper.
2. tools/with_test_display.py:18-35 validates the executable wrapper, adds its
   directory to PATH, and calls xvfb-run. Its command uses subprocess.run with
   no pass_fds argument. CPython Popen defaults to close_fds=True and an empty
   pass_fds tuple, so a future arm descriptor will not propagate without an
   explicit helper change.
3. The ROG-installed /usr/bin/xvfb-run script has SHA-256
   48ee444c30fdaaede4cc311644b30e554162e956f949b206858e37eb8ba1ae05.
   This read-only ROG system file is not pinned by source or the runtime
   manifest. Its lines 165-166 run Xvfb in a subshell that execs the server.
   Lines 182-185 start the test command after server readiness.
4. The verified wrapper is selected as Xvfb by PATH. m06_deployed_gate.py
   validates its exact script to execve the receipt-pinned Xvfb binary with
   the reviewed graphics environment. The wrapper therefore leads to the
   actual intended XLibre server process, not to an Xorg session.

The smallest M09 source increment is a test-launch-only endpoint handoff at
with_test_display.py and the existing Xvfb wrapper boundary. An authorized M09
fixture/controller creates the test arm. This helper only transports its FD.
The helper must explicitly preserve the intended endpoint across subprocess
launch. The server-side receiver must consume one bounded arm during
startup. The wrapper must exec the receipt-verified Xvfb binary. The helper
must close the endpoint before it execs the application test command. A focused
native witness must prove the endpoint reached the actual Xvfb PID and was
absent from the application process, and must verify the target executable,
credentials, CLOEXEC state, one-shot rejection, and teardown.

The system xvfb-run script is an additional trust boundary: the inspected ROG
copy inherits the helper's descriptors while managing Xvfb. Its source does
not close a passed descriptor in the parent after it forks the server. The
test-host copy and package identity are not pinned in the saved runtime
manifest, so their exact FD behavior must be established before qualification.
The implementation must either close that duplicate in the controlled
qualification launcher or document and test why the still-open copy remains
inside the authorized trusted launch owner. Do not claim exclusive server
custody until the independent witness confirms the parent, Xvfb child, and
application descriptor state.

This test-only endpoint handoff would provide M09 X server control evidence
using the real patched Xvfb process with a software display. It would not
prove physical scanout or integrate observer bootstrap into a final production
spatial session. The external production Xorg/session owner remains unresolved
as a separate session-integration question. That uncertainty does not block
the M09 Xvfb qualification path. Keep the endpoint separate from
HostSessionConfig's compositor/broker descriptors and SessionLaunch's existing
native-config and child-handle channels. Preserve XACE as the active baseline.

Worldd seat binding, independent live server identity resolution, probe
receipt production, and native end-to-end observer qualification remain
separate requirements. No production bridge or test is implemented here.
