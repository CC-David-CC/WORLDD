Framing and bounds

The complete artifact contains exactly three length-delimited Protocol Buffer records.
Their payload order is Arm, ObserverPress, ProbeReceiptBatch.
Envelope protocol_version is one. stream_sequence is exactly one, two, three.
Every record repeats the same fixture session, arm, and native_session.

The finite decoder accepts immutable bytes only. It never reads a descriptor.
Frame lengths must use canonical protobuf varints.
Payload encodings must equal deterministic serialization after discarding unknown fields.
This rejects unknown fields, duplicate scalar encodings, and noncanonical wire encodings.

Source-checked protobuf-c ordering compatibility:
The generated envelope field descriptor array is ordered by tags one through eight.
Its arm/observer_press/probe_receipts fields precede native_session despite declaration order.
Installed protobuf-c.h:686 requires descriptors sorted by tag number.
ROG has libprotobuf-c-dev/libprotobuf-c1 version 1.4.1-1ubuntu4.
Upstream v1.4.1 protobuf-c/protobuf-c.c:1472-1531 iterates that descriptor order when packing.
oneof_field_pack() at :1156 selects the matching numeric field ID in that same traversal.
unlabeled_field_pack() at :1218 omits default values, matching proto3 field omission.
Generated wrappers call protobuf_c_message_pack() directly.
Thus tag-eight declaration placement creates no source-level packing-order mismatch.
No field declaration change is needed for this ordering check.

Its SHA256 is 5af483efb77b6c60afce921ff361cff5320b2a80698f6e7fb0356c49b48933a7.

The maximum payload is 4,096 bytes. There are exactly three records.

The receipt batch contains at most 32 entries.
Limits require exact positive integers and may only tighten these ceilings.
Booleans, floats, zero, negatives, and excessive limits fail closed.

A deadline-aware descriptor collector remains unimplemented.

Native snapshot requirements

Arming requires authenticated ordinary XI2 precondition actions for both actors.
Pin all four devices per actor from those receipts and checked hierarchy roles.
Require idle pre-arm replay/frozen state under the reviewed lifetime contract.
At observation, resolve all eight devices again and validate epochs and pairings.
Check the recipient is Running and the surviving popup is mapped and realized.
Check client/window ownership, labels, epochs, and spatial generation.
Any invalidated arm, missing device, missing class, or changed lifetime must fail.
Do not replace a removed old device with an empty native state.

The observer captures its first qualifying outgoing XI_ButtonPress once.
It copies the four old devices' actual corresponding native down arrays at that callback.
Pinned XLibre f844d7a86c10fd5cc89083e7daf97b862b8ca1fd defines DOWN_LENGTH as 32 bytes.
Keyboard devices report KeyClassRec.down. Pointer devices report ButtonClassRec.down.
Each bitmap must report 256 bits, exactly 32 bytes, and state_complete true.
All four typed old identities must occur exactly once.
Any set bit fails. Short zero-filled data never counts as release.
snapshot_complete means every required pin and native state check succeeded.
This flag cannot substitute for those future native checks.
Native focus/grab diagnostics and postdown arrays are outside this decoder's release assertion.

Explicit proof boundary after main-window destruction:
This schema records complete native key/button down bitmaps only.
It does not encode native focus, grabs, capture, drag state, or their cancellation.
Clear down arrays and a correlated peer press do not prove those controls were released.
They cannot alone close every balanced-control requirement in root AGENTS.md.
Existing strict surviving-window release-event selectors remain mandatory and unchanged.
Their evidence does not fill the destroyed-target focus/grab/capture gap.
Native focus/grab/capture proof after destruction remains pending source-backed integration.
This increment invents no new focus/grab wire fields or native query API.

Observer ordinal must equal one. Later events cannot replace the snapshot.
The callback monotonic time must lie inside a positive, strictly increasing arm interval.
The event must be nonsynthetic XI_ButtonPress with the exact nonzero button detail.
Recipient, window, pointer master, source slave, and their lifetimes must match the arm.
Overflow, disconnect, missing snapshots, and invalidated arms fail qualification.
No fabricated protobuf fixture proves these native conditions occurred.

Independent probe receipts

Use reviewed probe source 9b24f170a04351115c5e0eb19352eb330591248d with --xi2-receipts.
Existing core-mode selectors and their expectations stay unchanged.
ProbeReceipt preserves receipt_ordinal, event_type, deviceid, sourceid, xid, detail, time, and synthetic.
The batch preserves all XI2 key, button, and motion receipts from its watermark.
Intervening releases, keys, and motion must not be filtered out.

The supervisor drains prior receipts before arming and records the watermark.
The batch starts at watermark plus one, with contiguous ordinals and no wraparound.
The validator finds the first ButtonPress sharing the pinned peer pointer master or source slave.
Using either identity detects wrong-pair presses before an apparently correct later press.
That first candidate must be the final receipt and match both pinned identities exactly.
Its target, type, detail, and X event time must match the observer tuple exactly.
An earlier wrong peer press or later replacement fails.
Synthetic input, unknown event types, invalid IDs, gaps, duplicates, and missing presses fail.

The supervisor authenticates the independent probe channel.
It attaches trusted recipient/window/device/source epochs in ProbeReceiptContext.
Those epochs are supervisor context, not native fields received from the probe.
The enclosing record binds the context to the fixture arm/session and native session.
X event time is matched exactly. It is not compared with monotonic time.
Only live channel integration can establish that the batch is complete and unfiltered.

Generation proposal; shared CMake and Meson files remain unchanged

The schema is standalone. Generate flat bindings from its directory.
Use the same flat native_input_observer_pb2 import as both Python source files.

CMake proposal:

set(observer_schema_dir "${CMAKE_CURRENT_SOURCE_DIR}/proto/spatial/testing/v1")
set(observer_python_dir "${CMAKE_CURRENT_BINARY_DIR}/python")
set(observer_python "${observer_python_dir}/native_input_observer_pb2.py")
add_custom_command(OUTPUT "${observer_python}"
  COMMAND ${CMAKE_COMMAND} -E make_directory "${observer_python_dir}"
  COMMAND protobuf::protoc --python_out=${observer_python_dir}
          --proto_path=${observer_schema_dir} ${observer_schema_dir}/native_input_observer.proto
  DEPENDS proto/spatial/testing/v1/native_input_observer.proto protobuf::protoc VERBATIM)
add_custom_target(native-input-observer-python-protobuf ALL DEPENDS "${observer_python}")
