Wire additions
Entity.application_slot uses field12 and is valid only for SURFACE_SLOT entities.
ApplicationSlotBinding stores workspace, application, native server identity, and opaque surface identity.
The surface identity includes the compositor incarnation and a monotonically assigned surface serial.
It is not an XID, PID, filename, actor credential, or application-provided property.
A server or compositor restart must not bind a replacement through a reused XID.

ActorActionRequest.application_surfaces uses field32. Its result uses ActorActionReply.application_surfaces field9.
ActorApplicationSurfacesRequest requires protocol_version1 and an application_id returned by the production broker.
It searches only the actor's explicitly selected, available workspace.
Remote application discovery remains unsupported. A local transport grants no additional actor rights.
Require fresh workspace access, application observation, and world observation authority.
Native application groups must pass the ordinary broker checks before any metadata leaves worldd.
Return only mapped top-level surfaces that are unplaced or in the actor's current room.
The reply excludes XIDs, window properties, names, commands, paths, and other application metadata.
Return a fresh32-byte actor-session discovery receipt for each exact surface generation and application identity.
Receipts identify checked metadata. They never cache permission or grant control.
A successful discovery replaces that actor's prior receipts. Connection, workspace-selection, and closure barriers clear them.
At most64 current receipts exist per actor. No receipt or authorization snapshot is persisted.
Discovery uses the existing controlled read/input outcome. Checked denial cancels held input and permits a fresh proposal.
Malformed or uncertain exchanges retain the existing strict fencing contract.

ActorActionRequest.application_place uses field33. Its result uses ActorActionReply.application_placement field10.
The request requires protocol_version1, operation_id16 bytes, discovery_id32 bytes, transform, size, and expected world revision.
An omitted room means the actor's current room. An explicit room must equal that room.
Require current world placement authority, workspace access, workspace attachment authority, and application observation.
Validate the exact receipt, application attribution, actor context, surface generation, reach, facing, and room colliders.
Recheck authorization fences and context immediately before the revision-checked durable commit.
The new slot stores the requested transform and size. It does not launch, copy, select, or control an application.
Actor movement during placement preparation invalidates the request instead of silently changing its target context.
Placement uses strict mutating errors. An uncertain result must not be replayed as a new operation.

Durable operation and attachment
Use existing world entities for geometry and the existing workspace_presentation_ops journal for exact operation identity.
Journal kind4 is application-slot creation. Its result starts with WAS1 followed by the committed Entity protobuf.
The entity and receipt commit in one SQLite transaction. This is not a transaction over X, files, or processes.
The same operation/principal/digest returns the existing unchanged slot. Different context conflicts.
A removed or changed slot remains a stale receipt. Its operation cannot recreate or retarget it.
An exact actor retry first checks current world placement rights, workspace access, workspace attachment rights, and application observation authority.
It then returns the stored receipt before checking live native application state. This preserves recovery after a lost reply and app exit.
The retry retains the actor session's exact discovery receipt and request digest. It neither restores the app nor changes geometry.
Ordinary world.create cannot synthesize an application binding. Ordinary updates cannot change binding identity.
No SQL table or schema-version change is required. The new typed entity payload requires this schema-aware runtime.
Older binaries reject unknown entity fields. Never open an application-slot world with an older candidate.
Slot attachment is reconstructed only from an exact live native identity match.
A missing surface leaves durable geometry unbound. No guessed XID or old input is restored.
Bindings are indexed by world revision. Do not rescan all durable bindings for every unchanged frame.
Application observation and control retain separate broker checks.
Bound-slot observation also checks world representation view. Input additionally requires representation use.
World revocation must retire held input and foreground pixels through existing checked cancellation and clearing paths.
