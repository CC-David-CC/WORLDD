# Copy cleanup pre-dispatch contract (2026-10-18)

A prepared broker scope may be removed without a bound copy journal only when its exact retained root identity matches and its owned scope proves supplied code could not have run. `ProcessScope` mints this fact only inside `OwnedDrainedTree`. The sticky bit becomes true before attempting startup-gate release, because a failed send may be ambiguous. It also becomes true before external payload attachment. It never resets.

An unbound cleanup callback first validates the callback tree against the retained broker identity. It may then return without producing copy outcomes only when the sticky execution bit is false. The ordinary bound-journal reconciliation path remains unchanged. If execution may have run, an unbound callback still rejects even after the cgroup empties. The process scope and copy evidence remain for recovery. Empty population alone does not establish that no worker was dispatched.

Focused core controls check the prepared-tree false state, post-gate sticky state after a real `/bin/true` exits, and preservation of an exact post-gate scope when cleanup rejects. The test contains an intentionally retained owner in a child process, exercises stop rejection, and performs explicit exact cleanup afterward. It does not exercise destructor-failure behavior. A full `AuthorityLaunch` issuer-denial integration control and a broker child failure after gate release but before bootstrap ACK remain required native smoke checks; they are not claimed here. The issuer-denial smoke must also assert the rejected candidate leaves no child cgroup beneath the fixture-owned parent. The cold-before-ACK smoke must assert the execution-possible unbound child remains quarantined and produces no fabricated cleanup receipt.
