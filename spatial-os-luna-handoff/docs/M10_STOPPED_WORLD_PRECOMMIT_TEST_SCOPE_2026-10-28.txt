Finding

The failed `world-participant-native` cases start worldd directly. They pass a
native compositor credential, but do not use AuthorityLaunch or its independent
guardian channel. The issuer records precommit obligations only for active
generations that registered a native guardian. These direct fixtures therefore
let IdentityRevoke commit without a native fence. Their queued X events then
reach the application after both worldd and spatialwm resume.

On sb16, both cases failed in candidate b4070e2. The issuer barrier remained
pending with two participants. The independent application probe recorded one
F1 press and release, plus one pointer press. XLibre delivered requests it had
already received. This does not isolate an XLibre defect. It also does not prove
the production supervisor path is safe.

Contract correction

Stopped-world precommit is a production-supervisor contract. Do not use direct
worldd component fixtures to claim or test that contract. Replace the direct
worldd key and pointer cases with exact supervisor-launched cases. Keep the
existing supervisor key case. Add a first-pointer case that starts without a
registered native seat. Confirm each requested renderer input was newly queued
by checking trace bytes written after that action began.

The direct fixture cases were removed from the mandatory M10 selector set. The
new supervisor cases preserve the key and first-pointer obligations. The existing
M10 fixture still tests seat preparation, server fencing, and cancellation in
the direct worldd component path. Production native sessions must continue to
use AuthorityLaunch and its guardian registration.
