M10 native guardian lifetime, 2026-10-26

Status: UNQUALIFIED component repair. Issuer precommit integration and
end-to-end production supervision qualification remain incomplete. The
stopped-world issuer-commit failures remain open. This document does not qualify
M10 or certify all XLibre input paths.

Finding
The guardian prototype acknowledged seat registration but had no native
lifetime relationship with that seat. Killing the guardian left the owner seat
usable. The reproducer failed on sb16 and sb16-2. Later key requests returned
NO_FOCUS rather than FORBIDDEN. The existing test uses an unfocused seat, so
this first reproducer proves the missing fence, not application delivery.

Ownership
This is a missing contract in our Spatial input extension and guardian
integration. It is not a reproduced upstream XLibre vulnerability. Existing
seats are connection-owned. An independent guardian needs an explicit native
lifetime binding before its registration receipt can be trusted.

Stopped-world input finding
The issuer-commit key and first-pointer failures do not currently isolate an
XLibre defect. The test stops worldd and spatialwm after worldd has queued an
input command to the compositor. The issuer commits revocation while neither
process can act. Since production has not registered an independent guardian,
the X server has received no seat revoke. When resumed, spatialwm submits the
queued command and the server accepts the still-active seat. The issuer barrier
remaining pending is correct; it reports that worldd has not consumed and
settled the revocation. It does not provide precommit cancellation.

The separate native server check explicitly revokes the prepared seat through
an independent compositor credential while the world and compositor are
stopped. After resume, the queued first-pointer press does not reach the
application. This exercises the server's seat-revoked check and supports the
conclusion that this targeted path works when the revoke reaches XLibre first.
It is not a complete XLibre audit and does not cover events already delivered
to an application connection before the fence.

Required integration
The issuer currently commits IdentityRevoke in one transaction, then records
postcommit obligations for authority participants. Worldd receives those
events and cancels inputs. This order cannot meet the stopped-world contract.
The next design must durably prepare a revocation intent, stop matching seat
registration, collect checked native-fence receipts from every guardian, and
only then commit the revocation. A missing guardian must leave the operation
pending and uncommitted. Recovery must replay the same intent and fence exact
seat registrations idempotently. Production supervision must keep guardians
independent of worldd and spatialwm.

Uncommitted worktree seat-registration wiring
The per-world spatial-authority-supervisor now creates a private checked
world channel when it launches a native compositor target. It retains an
independent NativeInput connection and a durable seat ledger. It runs
NativeSeatGuardianWorldService while the world child is alive. worldd receives
the other channel endpoint and constructs NativeSeatGuardianClient. On first
input, Actors::send_input prepares the seat, registers its exact binding, checks
the returned SeatRegistrationReceipt, then submits the input. These are
uncommitted worktree edits, not code in branch HEAD or the current candidate.
The prototype-only two-role NativeSeatGuardianService is not the production
endpoint. This worktree path still needs an end-to-end supervisor and worldd
test, and the supervised launch configuration must require the guardian where
M10 depends on it.

Extend the issuer participant protocol with durable precommit fence intents.
For each active supervised world generation, the issuer records an obligation
before the target revocation can commit. Its supervisor fences matching seats
through its independent NativeInput, records the exact result, then acknowledges
the intent. The issuer commits only after every active generation acknowledges.
Worldd can remain stopped during this process. After commit, the existing
revocation feed and completion barrier continue to cancel actor state and prove
settlement. A stopped or missing supervisor leaves the intent pending. On
restart, the same durable intent is replayed against the ledger, and confirmed
fences are not applied to a different seat registration.

Private schema addition
input.proto adds Seat guard at Request field 13. Existing fields, operations,
and acceptance locks are unchanged. The operation adds a lifetime dependency;
it does not grant actor authority, input ownership, or permission to steer input.

The caller must use an independent native connection with the same issued
compositor credential as the seat owner. Binding is idempotent for that exact
connection. A different guardian cannot replace it. The owner cannot guard its
own seat. A revoked seat cannot acquire a new guardian.

When the server observes the guardian connection closing or entering retained
client state, it releases held input and permanently revokes the seat. The
owner may still inspect, cancel, or close it. Unrelated seats remain usable.
Applications stay alive. Owner close removes the seat, so later guardian close has no stale seat
pointer to follow. This does not detect a live but stopped guardian connection.

Guardian registration and lifetime
NativeSeatGuardian persists registration, binds the exact native seat, and
checks native connection health before acknowledging registration. Any failed
binding prevents acknowledgement. A crash before binding cannot authorize the
first input; worldd awaits the receipt when the supervisor channel is present.

Both guardian service variants close their dedicated native connection on
failure and destruction. This asks the native server to fence every seat bound
to that connection even if the caller catches the service exception. The
uncommitted worktree wires NativeSeatGuardianWorldService into the
production supervisor for seat registration. It does not yet consume issuer
precommit fence intents.

Remaining integration gap
The supervisor launch path creates the channel pair for a native compositor
target, retains NativeInput and the guardian ledger, constructs
NativeSeatGuardianWorldService, announces readiness, and pumps it independently
of worldd and spatialwm. worldd constructs NativeSeatGuardianClient from the
inherited endpoint. Actors::send_input prepares the seat, builds the binding,
requests registration, validates the receipt, and checks cancellation state
again before submitting input.

The missing production contract is issuer precommit integration. The production
world service handles seat registration only. It does not receive durable
revocation intents or return a fence acknowledgement to the issuer. Identity
revocation still commits before participant completion, so a stopped world and
compositor can retain a queued native action after issuer commit. Existing
standalone guardian tests do not prove the full supervisor-to-worldd launch
path or issuer precommit behavior.

Issuer precommit implementation constraint
Issuer::revoke currently advances security_revision, inserts the revocation, and
snapshots postcommit authority_barrier obligations in one transaction. The TLS
server is a single nonblocking event loop that advances each peer by one bounded
step. Blocking inside IdentityRevoke while waiting for supervisor acknowledgments
would stop the event loop from receiving those acknowledgments. The fix therefore
needs a durable asynchronous PREPARING state: record the signed target and
fence obligations, return a pending operation identity, deliver intents through
the retained participant path, and commit the revocation only after every
supervisor reports its checked native fence. Pending preparation must prevent a
new authority generation from bypassing the obligation set. The existing
postcommit authority barrier remains a separate settlement proof.
The issuer must authenticate each precommit receipt with the registered
supervisor key. A participant TLS connection alone is insufficient because the
world process must not be able to claim that the independent guardian fenced its
native seats. The retained supervisor must set the generation's guardian flag
from its live guardian ownership, rather than forwarding a child-supplied flag.
