Purpose

This draft maps the root M09 requirements to the frozen production source. It does not change locked tests or acceptance contracts. It records source evidence, not test execution or milestone qualification.

Normative scope

M09 requires one controller per application group, authorized observers, and concurrent controllers for independent applications. A transfer must release held input before granting control. Stale surface generations must fail. Observation and control revocation must take effect immediately. Read-only authority must not control a writable application. Revoking a controller must not stop application execution when execution authority remains valid.

Control acquisition, sharing, and handoff

Separate observation and control authority

- Workspace authority computes observation and control as separate application-scoped rights. See src/workspace/authority.cpp:481-489.
- A broker access result grants control only when observation and control rights both pass and the actor's effective workspace rights cover the application's stored execution rights. This denies a read-only actor control over a writable application. See src/workspace/store.cpp:1787-1839.
- Actor observation filters surfaces through application observation decisions and revalidates authorization fences after rendering. See src/world/actors.cpp:1101-1147 and :1262-1318.
- Streaming observation checks authority before each output write. See src/world/identity_sessions.cpp:968-984.
- Source tests explicitly cover read-only denial, observation without control, observation revocation, post-render revocation, and queued observation revocation. See tests/core/test_world_application_control.py:125-138, :158-161 and tests/core/test_application_observation.py:203-260.
- Classification: implementation PRESENT in source. Runtime results are not asserted by this draft.

Revocation and continued application execution

- Workspace authority changes call ControlLeases::tick, which revokes the lease and emits an event while retaining the group reservation. It does not terminate the process. See src/workspace/main.cpp:330-348 and src/workspace/control.cpp:109-120.
- BrokerClient validates and records revocation events. Worldd notices inactive leases, cancels native input, then releases the broker reservation. The server loop calls flush_input while servicing and waiting. See src/platform/broker.cpp:446-462, :479-487, :795-802; src/world/actors.cpp:871-889, :928-948; src/world/server.cpp:43-64.
- Process execution is checked separately against the process's stored rights. Store reconciliation removes a job only when those execution rights are no longer valid. See src/workspace/store.cpp:1841-1885 and :1978-1984.
- Source tests cover idle control revocation with continued execution, observation revocation, actor revocation, and process-wait overlap. See tests/core/test_world_application_control.py:151-165, :249-280 and tests/core/test_application_control_lease.py:135-145, :182-214.

Focused M09 acceptance cases to freeze after review

1. Group membership: create main, dialog, and popup windows from multiple X connections bearing one application identity. They share one control reservation. A second actor requesting this group receives BUSY. Different application groups remain independent. Cross-workspace and cross-application transient hints do not merge groups.
2. Independent controllers: two actors control two applications concurrently. A second actor cannot control the first application's group until native cancellation completes and the prior release is acknowledged.
3. Balanced transfer: hold a modifier, key, button, focus, and drag capture. Trigger voluntary transfer, actor revocation, observation revocation, controller disconnect, and surface destruction. Independently witness every release before the next controller's first event.
4. Generation fence: resize, unmap/remap, destroy/reuse an XID, and replace an application surface during broker authorization. No input may reach the replacement through an old handle.
5. Authority separation: observation-only actors cannot control. Read-only actors cannot control writable applications. Verify allowed read-only control and authorized observers as positive controls.
6. Revocation and execution: revoke only the controller's observation/control while the process retains its own execution rights. Confirm input release, no more observation pixels, live responsive application, and successful later control by another authorized actor. Separately revoke process execution rights and confirm the process is stopped.
7. Observation race: revoke observation before rendering, after rendering, and while a local observation output is queued. The actor receives no post-revocation pixels or stale metadata. Remote application streaming remains out of scope.
