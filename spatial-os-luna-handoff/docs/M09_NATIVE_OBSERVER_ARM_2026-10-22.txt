Implemented behavior

The private parent-owned endpoint accepts one setup and then one bounded arm.
Consumption latches before parsing and native resolution. Replay closes the private endpoint.
Each packet retains parent credentials, descriptor rejection, canonical Protobuf checks, and byte limits.
The server retains owned copies of the accepted setup, native pins, and arm.
EOF, deadline, reset, and refusal release those copies and close the endpoint.
The setup deadline can shorten the startup budget. Arming cannot extend it.

Arming compares session, arm, application, presentation, window, client, and device identities.
It re-resolves all native setup pins. Reused identifiers cannot inherit an earlier native epoch.
The old seat must control the selected application with the expected target and focus generations.
Its tracked keys and buttons must exactly match the arm. The peer seat must be idle.
These checks read existing native state. They do not acquire or transfer application control.
An evidence refusal leaves existing native application routing intact.
