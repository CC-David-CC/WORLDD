M07 execution schema v7 to v8 migration regressions
Date: 2026-10-14

Scope

This focused test set exercises stopped execution-registry v7 to v8 migration through the production `workspaced` executable. It does not change production code, schemas, migration contracts, or locked acceptance tests. The reviewed review03 behavior remains, with the diagnostic-oracle strengthening described below.

Source contract

- `src/workspace/store.cpp:258-309` contains startup refusal, integrity checks, the explicit v7-to-v8 transaction, creation of the two configured-state tables, and marking old active copy operations UNCERTAIN.
- `src/workspace/copy_journal.cpp:412-425` defines copy-journal schema v6, including `authorization_binding`, `copy_effects`, and its pending index.
- `src/workspace/main.cpp:167-193` parses `--migrate-v7`, requires stopped operation, and exits after migration.
- `proto/spatial/workspace/copy/v1/copy.proto:40-49` defines the request used by retained journal rows.

The fixture creates the historical v7 schema directly. It does not relabel a v8 database. It retains repositories, worktrees, operations, removals, workspaces, members, processes, copy policies, journal records, and external-effect records. It includes active phases 1 through 6 and terminal phases 7 through 9. Request bytes use generated `copy_pb2` serialization.

Named regressions

- `test_v7_fixture_matches_historical_shape_and_retains_all_rows`: verifies the historical tables and journal columns, without v8 tables.
- `test_ordinary_startup_and_wrong_version_flags_refuse_without_mutation`: default startup and mismatched v5/v6 flags preserve schema, rows, and version.
- `test_exact_v7_migration_adds_only_schema8_tables_and_preserves_journal`: adds only the two v8 tables, preserves legacy rows and effects, marks phases 1–6 UNCERTAIN/COPY_UNAVAILABLE, and preserves terminal rows.
- `test_repeated_migration_is_idempotent_and_normal_startup_reopens`: repeats migration and verifies normal startup exits zero at EOF without logical database changes.
- `test_foreign_key_corruption_refuses_without_partial_migration`: rejects invalid foreign keys before mutation.
- `test_migration_ddl_conflict_rolls_back_first_schema8_table`: verifies transaction rollback when the second v8 table conflicts.
