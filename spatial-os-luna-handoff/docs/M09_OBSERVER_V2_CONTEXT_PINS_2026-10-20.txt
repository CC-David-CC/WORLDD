Status: reviewed additive private source. Debug and ASan-UBSan object compilation passed. Full server build and native qualification remain UNRUN. The API remains incomplete.

## Change

The lifetime header adds separate v2-only value types and declarations. Existing v1 pins and snapshot behavior remain unchanged.

SpatialObserverPinNativeClient records a live client index, observer session, client epoch, and actual security role. It classifies APP through SpatialSecuritySameApplication(client, client) and the namespace getter. It classifies privileged connections through SpatialSecurityPrivileged; SpatialSecurityInputController distinguishes COMPOSITOR from SUPERVISOR. It requires configured security and a running non-server client. APP labels are copied only for APP. Privileged selection scope is not copied as application identity.

SpatialObserverSnapshotContextV2 accepts an existing device-set pin and trusted APP target-window pin. It resolves the target XID afresh and checks mapped/live state, owner pin, and window epoch. It samples active grabs and focus synchronously. It emits a focus or grab window identity only when its pointer equals that known-live target. It never dereferences an unknown focus, grab-window, or confine-window pointer. A non-null confine pointer is represented only when it equals the target.

A grab owner is pinned independently from the target owner. Pinned DIX ActivateImplicitGrab sets resource to the event recipient's clientAsMask, sets window to the event target, and selects XI2 grabs for XI_ButtonPress (dix/events.c:2153-2197). XI2 delivery is attempted first and successful delivery stops propagation (dix/events.c:2888-2921). Therefore a privileged XI2 probe can own the active implicit grab on an APP-owned target. The helper does not require owner equality with target owner.

For an active grab, the helper checks nonzero resource, exact device pointer identity, and exact target pointer identity. It derives the owner from the resource client-index bits using dixClientForXID, then validates that live client's security role and epoch. It does not call dixLookupResourceOwner: that helper requires a registered resource lookup (dix/dixutils.c:224-246), while active implicit grabs can carry a client mask and CreateGrab uses FakeClientID (dix/grabs.c:218-254). Passive grabs are separately registered with AddResource (dix/grabs.c:529-568).

Incomplete input returns false with valid false and nonzero output sentinel bytes. No pointer escapes the synchronous call. No global grab registry or grab epoch was added. The v1 APP-only client helper remains unchanged.

## Lifetime and ordering evidence

Existing lifetime callbacks invalidate client epochs at retained/gone state (lifetime.c:46-54) and window epochs while the window resource is freeing (lifetime.c:56-64). Reset clears readiness before detaching callbacks (lifetime.c:66-75). Client shutdown releases active grabs before retained/gone callback (pinned dix/dispatch.c:3699-3762). Focus/window cleanup runs before window free (pinned dix/events.c:3031-3095, 5885-5935). Device teardown frees its active grab before the device (pinned dix/devices.c:1039-1049). Deactivate paths clear/free grabs (pinned dix/events.c:1664-1726, 1783-1822).

The helper rejects calls from in_input_thread() and does not take input_lock. The input thread holds that lock around driver read callbacks (pinned os/inputthread.c:176-185). The main event queue releases it before DIX event processing (pinned mi/mieq.c:522-588). This supports a synchronous DIX-dispatch snapshot without adding lock recursion. Source inspection does not replace compile/runtime validation.

## Invariants and limits

- Returned identities are values scoped by the current observer session and object epochs.
- Device identities are re-looked up and checked against existing device-set relationships.
- The target is re-looked up by XID, then checked against its APP owner pin and window epoch.
- Grab owner identity comes from the active grab resource's client index and live client slot. No GrabPtr, WindowPtr, or ClientPtr is retained.
- Only target-window joins are accepted. A real OTHER focus is represented only when it equals the target; any other focus, grab window, or confine window is incomplete.
- Sentinel focus values remain distinct. Absent focus class remains distinct.
- Active-grab owner may be APP, SUPERVISOR, or COMPOSITOR. The window owner remains separately pinned APP.
- No schema, decoder, serializer, capture, security policy, XACE callback, ordinary-client permission, or input behavior changed.
- Build, tests, sanitizers, native fixture, and runtime checks: UNRUN.
