ACTUAL PROBE AND SECURITY FINDINGS

There is no M09 producer or native fixture launch/receipt implementation. The integration summary says linking/arming the observer, authenticating probe provenance, and connecting native state to independent receipts remain unrun (M09_OBSERVER_FIXTURE_INTEGRATION lines 54-58). The fixture contract says the live descriptor collector and EventCallback integration are missing (M09_NATIVE_INPUT_OBSERVER_FIXTURE_CONTRACT lines 226-230). The v2 validator tests and synthetic records do not settle which X client will authenticate as the probe.

The existing generic xprobe is a separate X process. `harness/probe.py` launches it with DISPLAY and inherited environment, but passes no role credential or probe authorization argument (lines 11-26). `native/xprobe.c` calls XOpenDisplay (line 172), creates its own target window (181-186), and selects XI2 events on that window using XIAllMasterDevices (87-100). This proves a generic probe can own a window and subscribe in the test topology where it runs. It does not prove that probe authenticates as APPLICATION under the M09 secured profile.

The security-enabled policy resolves the role choice. `spatialpolicy.c:402-453` allows every extension to a privileged supervisor/compositor at line 404. For an application, the policy returns false unless the extension is explicitly allowlisted; the list contains BigRequests, XC-MISC, Shape, and selected Render requests (406-453). XInputExtension is absent. Therefore an APPLICATION probe cannot use XI2 selection under this policy. `test_application_input.py:11-14` also states its fixture selects no input events, so it supplies no contrary XI2 application proof. The generic XInput extension tests do not establish the M09 security role or credential.

The v2 draft currently has one `expected_recipient` joined to `expected_application` (decoder lines 170-174). `ObserverPress.recipient` must equal it (379), as must `ProbeReceiptBatch.recipient` (388-389). The capture arm requires recipient index to equal the application popup owner (capture.c:97-100); captured EventCallback recipient must also equal that owner (200-210). The schema includes application identities for both recipient and window (proto lines 7-13; ObserverPress and ProbeReceiptBatch lines 96-105). The proposed fixture contract says a window owner must match the expected recipient and label (fixture contract lines 38-50).

This is a confirmed incompatibility between the current draft contract/capture assumption and the secured XInput policy, not a confirmed production runtime defect. With an APPLICATION probe, the app/window-owner join is internally consistent, but the policy denies that client XI2 access. With a privileged probe, XI2 is allowed, but its role has no application label (spatialsecurity.c:150-164 and 408-410), and the current capture arm/callback insists the event recipient is the app window owner. The current capture code cannot represent the privileged independent probe as recipient. No M09 fixture exists to show a third approved route.

Do not change schema or security policy based on the generic probe alone. Primary must choose and document a real M09 probe path. Any fix must preserve actual role, client, window-owner and receipt identity. Options require a reviewed design decision: add a narrowly authorized privileged observation path with distinct probe recipient and app window owner, or define another production-authorized XI2 receipt topology. Do not grant XInputExtension to ordinary applications as a shortcut. The existing capture output attempt and independent probe receipt remain distinct evidence.

GRAB OWNER AND LIFETIME TRACE

Pinned `GrabRec` has resource, device, window and confineTo fields, with no owner pointer (include/inputstr.h:180-199). `CreateGrab` allocates a GrabRec and assigns `FakeClientID(client->index)` (dix/grabs.c:218-254). It does not register that GrabRec as an X resource there. `AddPassiveGrabToList` separately registers passive grabs as `X11_RESTYPE_PASSIVEGRAB` (dix/grabs.c:529-568). Active explicit and implicit grabs can therefore carry a FakeClientID that has no resource-table entry.

`dixLookupResourceOwner` is unsuitable as a universal owner resolver. Its implementation in dix/dixutils.c:224-246 first requires a registered resource via `dixLookupResourceByClass(..., RC_ANY, ...)`. That lookup returns failure when no matching resource entry exists (dix/resource.c:1196-1218). It can resolve registered passive grabs, but cannot be assumed to resolve active/implicit grabs.

The pinned DIX already resolves a grab's client bits with `dixClientForXID(grab->resource)` (dix/grabs.c:95 and 644). Its helper maps the XID client index to `clients[index]`; it returns a live table pointer only when one currently occupies that slot (dix/resource_priv.h:104-109). For a sampled active grab, this value must still pass the observer's live-client checks: nonnull, expected index, Running/not gone, security role/application label valid, and current observer client epoch. Never use the XID's client bits alone as identity.

The client teardown order supports a bounded synchronous sample. `CloseDownClient` calls `ReleaseActiveGrabs(client)` before it marks a retained client and invokes `ClientStateCallback` (dix/dispatch.c:3699-3731). The observer client callback invalidates its epoch for Retained/Gone states (lifetime.c:46-54). Device teardown frees its active grab before freeing device privates and the device itself (dix/devices.c:1039-1049). `DeactivatePointerGrab` and `DeactivateKeyboardGrab` free the active GrabRec (events.c:1664-1726 and 1783-1822). A passive grab's registered resource is freed when its window is destroyed (events.c:5944-5953), and normal registered-resource teardown also supplies resource callbacks.

Smallest safe lifetime API is a synchronous value snapshot from a live, pinned DeviceIntPtr in server dispatch. Read `device->deviceGrab.grab` only during that call. If null, report proven no grab. If nonnull, copy its resource XID, resolve the current client slot with `dixClientForXID`, validate/pin that live client and epoch, pin the grab window and optional confine window through existing safe XID lookup/owner pins, and check the grab device pointer equals the live pinned device. Return no pointer. A failed owner/window/device join makes the snapshot incomplete. The device pin epoch prevents a later device-ID reuse from matching.

No separate grab epoch or global grab lifetime registry is justified by the current proto: GrabIdentity carries resource, owner, window, device and optional confine window (proto lines 79-83). Do not add an abstract grab epoch. The synchronous sample relies on DIX's serialized dispatch and teardown ordering; primary should confirm the configured X server has no concurrent mutation path before freezing the helper. If that assumption fails, add only the specific lock or callback proven necessary.

Focus remains an open API detail. Current lifetime snapshot compares native focus pointers only to NoneWin, PointerRootWin, FollowKeyboardWin, or OTHER and deliberately never dereferences OTHER (lifetime.c:231-252). The window teardown path updates focus/reversion before resource destruction (pinned dix/events.c around 5845-5953). A later synchronous focus pin may read the real focus window's XID, perform `dixLookupWindow`, require the returned pointer to equal the live focus pointer, then apply existing window owner/epoch pinning. It must distinguish sentinel focus kinds and invalidate on lookup mismatch. Do not retain the raw focus pointer. Confirm the precise ordering in the selected native focus transition path before adding code.
