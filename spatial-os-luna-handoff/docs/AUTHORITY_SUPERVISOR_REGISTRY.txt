Owner-controlled authority supervisor registry
Status: isolated implementation in progress. No source integration or operator migration.

Invariant

Only an issuer-owner proof can bind a separate supervisor key to an exact participant registration.
Binding cannot adopt an active generation or clear any revocation obligation.

Additive protobuf contract

AuthoritySupervisorBind has participant_id field 1, registered_revision field 2, public_key field 3, and optional expected_revision field 4.
AuthoritySupervisorRead has participant_id field 1.
AuthoritySupervisorBinding has registration field 1, public_key field 2, and revision field 3.
IssuerOperation adds supervisor_bind field 12 and supervisor_read field 13.
AdminResult adds supervision field 8. IssuerReply adds supervision field 26.
Existing wire numbers and signing purposes remain unchanged.

Participant and key identifiers contain 32 bytes.
Registration revisions are positive signed-64-bit values.
The expected binding revision is mandatory and fits signed-64-bit storage.
Zero requests the first binding. Each successful mutation increments the binding revision once.
The returned registration contains the exact registered domains and issuer identity.
Requests use the existing signed issuer-administration challenge.
Read operations also require owner proof.

State and key separation

Reject nonexistent participants and mismatched registration revisions.
Reject binding or key replacement while any generation for that participant remains active.
Reject stale binding revisions without mutation.
Reject issuer, owner, registered service, and actor-enrollment keys as supervisor keys.
Reject use of a registered supervisor key for actor enrollment or service registration.
Several participant bindings may explicitly name one supervisor key.
The key receives authority only for those exact registrations.

A bound participant cannot activate through its service key alone.
Explicit supervisor launch authorization remains a subsequent required protocol.
Until that protocol exists, bound participant activation fails closed.
This registry does not provide a recovery receipt or retirement operation.
It does not alter applied revisions, active generations, or barrier obligations.

Persistence

Issuer schema version 7 adds authority_supervisor.
Its row contains participant identity, exact registration snapshot, supervisor public key, and binding revision.
Schema versions 1 through 6 require explicit migration.
Migration preserves issuer keys, policies, registrations, activations, and revocation history.
Migration creates no supervisor binding for an existing service.
Failed migration rolls back the table and version change.
Use disposable test databases only.

Historical migration fixtures must remove the new table when constructing older schemas.
Their target-version assertions change from 6 to 7.
Preserve all data-integrity and rollback assertions.
Record those fixture changes explicitly. Locked acceptance files remain unchanged.

The production client must validate owner challenge context and correlate each binding reply with that challenge.
Reject a mismatched participant, key, registration, revision, issuer, or proof.
Typed denial consumes the pending client proof context.

Supervisor launch authorization, fencing, checked recovery, and Spatial-M1 remain incomplete.
