Private broker authorization fence contract

Scoped authority replies and application-access batches carry a 16-byte process incarnation and a positive monotonic authorization epoch. The broker also exposes a private fence request that refreshes issuer state for the authenticated principal across every configured workspace authority before returning the current pair. Callers compare every collected decision pair with one final fence pair and discard the batch on any mismatch.

Application-access first completes issuer refresh, process reconciliation, reaping, and native checks. It captures the pair before evaluating the batch. Evaluation performs only local store and process-record reads. It returns UNAVAILABLE if the pair changes before the batch completes.

The epoch advances for observed issuer security revisions, actor or credential revocation transitions, actual durable grant or bootstrap revision changes, real workspace creation or membership changes, and service failure. Cache invalidation alone does not advance it. Epoch exhaustion disables authority. Each process gets a fresh kernel-random incarnation, so a restart cannot reuse an old fence pair.
Issuer security revision zero is a valid initial value, not an uninitialized marker. Once a baseline revision has been observed, a later revision increase from zero advances the epoch. Credential revocation preserves an otherwise valid actor and running workspace process while still advancing the fence epoch.

The private protocol change adds fields to ScopedAuthorityCheckReply and ApplicationAccessReply and adds request field 114 / reply field 113 for the fence operation. It exposes no grant records and changes no actor-facing schema. The authority store revision accessor is trusted internal code and does not authorize caller access.
