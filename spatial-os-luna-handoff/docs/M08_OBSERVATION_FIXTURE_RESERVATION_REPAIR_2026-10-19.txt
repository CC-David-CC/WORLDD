M08 observation fixture reservation repair (2026-10-19)

Cause

The observation fixture retains its bootstrap application and launches two
native witness applications. It raised default_policy.actor_default to cover
three applications, but production WorkspaceResources::prepare selects an
explicit workspace policy when one matches the launch request. Full-gate
workspace one has a 256 MiB / 32-process actor default. Each application
profile permits 128 MiB / 16 processes, so the third application exceeds the
selected actor reservation. The later observation, control, and pixel failures
are the same setup defect.

Repair

Fund the selected explicit workspace policy for the fixture's three same-actor
application reservations. Fall back to the default policy when no explicit
workspace entry matches. Calculate only memory, swap, and process headroom,
the dimensions Group::fits reserves. Refuse insufficient workspace or broker
headroom before changing either actor field. Preserve all other policy fields,
application maxima, unrelated workspaces, and the broker and manager envelopes.
No production resource policy is changed.

1. CTest observation-resource-fixture-tooling: generated protobuf regression
   checks default-policy fallback, explicit workspace selection, unrelated
   policy and profile preservation, and refusal before mutation when workspace
   memory capacity is too small.
2. Re-run the exact failed callers on both sb16 and sb16-2 in Debug and
   ASan-UBSan: core #154 application-observation test_application_scope_filters_other_live_application;
   core #155 world-application-control test_independent_applications_allow_simultaneous_actors;
   core #156 actor-pixels test_other_application_scope_does_not_export_its_pixels.
