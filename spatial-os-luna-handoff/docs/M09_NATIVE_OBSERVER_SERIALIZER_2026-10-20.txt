## Contract and proof boundary

`spatialinputobserver_serialize.c` uses generated protobuf-c bindings from the
versioned schema. It emits exactly two canonical length-prefixed records:
Arm sequence 1, then ObserverPress sequence 2. It emits no probe receipt record.
The supervisor must append the independently collected ProbeReceiptBatch.

The serializer rejects wrong capture phases, failures, sessions, device pins,
roles, object epochs, labels, event tuples, timestamps, or incomplete native states.
It checks recipient and popup label equality and requires all device roles once.
It uses validated captured role sets to encode the schema's required pair fields.
It verifies GenericEvent type (including no synthetic bit), nonzero XI extension,
XI_ButtonPress tuple, fixed bitmap lengths, and consistency between the native
GenericEvent length, captured packet byte count, and XI2 header/class bounds.
The capture callback already checked the extension against the server's XI opcode
and validated the raw packet; the serializer does not retain or reparse raw pointers.
The lifetime pin path checked the live master pairing and slave attachment.
The serializer copies the actual 32-byte key/button down arrays, including set bits.
The parser must reject retained native input. COLLECTED does not mean release succeeded.

The output buffer stays untouched and output length stays zero on rejection.
The serializer packs into bounded local buffers before copying to caller storage.
Each protobuf payload is limited to 4,096 bytes. Output capacity is checked exactly.

Trusted context contains fixture nonces, actor and issuer references, spatial generation, receipt watermark, and deadline. The serializer authenticates none of them.
Future supervisor/channel work must authenticate the context, bind native session to
one retained server process, validate spatial generation against live authority, and
bind its independent probe stream and EOF/deadline to this arm. Do not deserialize
external epochs into native pins or expose an ordinary X client endpoint.

The schema proves only native key/button down bitmaps. It does not prove focus,
grab, capture, drag, or complete release cancellation. Those claims remain pending.
The serializer is not linked into XLibre and has no descriptor or socket API.

## Selected regressions and source validation

The authored C-to-Python regression source covers:

- Valid generated protobuf-c encoding of the two native records.
- Retained key and button bitmaps preserved in output and rejected by the Python oracle.
- Rejection of stale session and pin, invalid role, oversized label, wrong event tuple,
  stale timestamp, and wrong capture phase.
- Rejection of synthetic-bit and non-GenericEvent headers, truncated packet lengths,
  and mismatched GenericEvent declared versus captured lengths.
- Exact-capacity success, one-byte-short failure, and no partial output on failure.
- Python-side stale native session, role, label, event tuple, and time mutations,
  each checked against its intended parser rejection reason.
- Exact immutable bytes from the two C frames plus a canonical test-only synthetic
  receipt frame, validated against a fixed independently constructed expected context.
  Held-key/button cases assert their nonzero bitmap before checking the parser's
  retained-input rejection.
