Fixture correction after initial runtime diagnosis

The initial db490 sb16 Debug run passed 15/16 module methods. The new two-world regression failed while starting the second real workspaced broker: TLS material requires an owned private parent directory. The workspace_two() helper created its root with the default 0755 mode, then stored TLS client material beneath it. Production TLS validation correctly requires the immediate parent to be owned and private. The fixture now creates workspace-two with mode 0700. Production checks and TLS file modes remain unchanged. Second fixture diagnosis and correction

The corrected-v2 sb16 Debug run also passed 15/16 methods. The new regression failed at its initial source observation: it expected workspace-one-room but observed the world entry room. Both workspace helpers use scoped_world(), whose default authenticates the actor before the production driver starts. The actor therefore already has a persistent entry context, and production correctly ignores the later spawn request. The regression now defers fixture authentication only while creating its two worlds. The production driver performs initial authentication with the explicit source spawn, then creates the destination actor with its requested spawn. The room, pose, workspace, and repeated-return assertions remain unchanged. Corrected runtime remains pending.
