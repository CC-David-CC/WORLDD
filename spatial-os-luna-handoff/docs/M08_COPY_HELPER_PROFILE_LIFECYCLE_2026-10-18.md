# M08 profile-matched copy helper lifecycle

The M08 local gate wraps only the full per-profile core CTest stage with `tools/with_copy_worker_helpers.py`. The wrapper checks the selected build using `copy_fixture_profiles.instrumentation_preflight`, then installs that profile's copy tree and finalize helpers at the fixed production paths.

The wrapper refuses every host except sb16 and sb16-2. Its `--preflight-only` mode reports candidate hashes, instrumentation, previous helper state, and process visibility without installation or restoration. The runtime mode records exact prior helper state, backups, and privileged command output under the requested external evidence path. A fixed read-only inspector runs under `sudo -n` and excludes its own PID and only the ancestor `sudo` chain for this inspector invocation, whose command lines carry the explicit helper paths. An unreadable process entry blocks the operation. It serializes owned wrapper runs with a private per-user `flock`. It starts CTest in a new session and handles SIGTERM/SIGINT by signaling only that recorded process group. It confirms the group is empty before restoring. If the group remains active, it preserves helpers and fails cleanup. The child has a 14,340-second internal deadline, one minute before the M06 core-stage timeout, so the wrapper can restore helpers before the gate timeout. It refuses unsafe helper files, an active helper process, or a changed helper during cleanup. It restores prior bytes and metadata, or confirms both paths absent. Unconfirmed restoration fails the wrapper and leaves its recovery receipt.

M06 and M07 do not enable this prefix. Their default stage commands remain unchanged. M08 enables it for each selected profile, so Debug and ASan-UBSan use their own matching binaries. The inherited `workspace-copy-engine` runner may temporarily install the same pair inside this scope; it then restores the wrapper's candidate pair.
