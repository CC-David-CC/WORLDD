Defect: Animated cursor timer leak
Status: Confirmed. A tested fix is in open PR #3860.
Affected file: Xext/render/animcur.c
Affected function: AnimCurUnrealizeCursor
Cause: AnimCursorCreate allocates a timer. Final cursor destruction does not free it.
Impact: Each destroyed animated cursor leaks 40 bytes on the tested LP64 build.
The leak occurs during ordinary operation, including cursors that were never displayed.
Evidence: Fresh upstream master 71f28aec8b45f52051c5264ca5a40c5babad369d leaked 2600 bytes in 65 timer allocations.
Fix: Call TimerFree(ac->timer) inside the existing screen-zero cleanup block, before freeing frame cursors.
Validation: The minimal fix passed 32 unused and 32 displayed cursor lifecycles on one screen without sanitizer errors.
Limit: Two-screen testing still fails in separate Xvfb cleanup. It does not establish full two-screen acceptance.
PR: https://github.com/X11Libre/xserver/pull/3860

Proposed patch:
1. In AnimCurUnrealizeCursor(), inside the existing pScreen->myNum == 0 block, call TimerFree(ac->timer) before releasing frame cursor references.
2. Keep the screen-0 guard so cleanup runs once across screens.
3. Do not use TimerCancel(); it removes the timer from the queue but does not free its allocation.

Regression checks:
- Create and destroy an animated cursor without displaying it.
- Display, cancel, then destroy an animated cursor.
- Repeat creation and destruction and confirm no OsTimerRec leak.
- Run with multiple screens and confirm no double-free.

Status: minimal fix is already in PR #3860: https://github.com/X11Libre/xserver/pull/3860. The disposable upstream witness passed one-screen lifetime cases after the fix. The two-screen shutdown test exposes a separate Xvfb defect.
