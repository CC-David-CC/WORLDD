EXISTING NATIVE IDENTITIES AND BINDING SEAMS

The native server already owns the relevant objects. Names below refer to source at pin `584ed4e17426a4a8cb9eed1f4ad462bb68d23bbd`.

- Actor seat: `SeatRec` in `server/xlibre/spatialinput.c` stores `owner`, monotonic `id`, four genuine devices, `target` plus `target_generation`, `focus` plus `focus_generation`, held keys/buttons, and `application`. `open_seat()` creates and attaches the master/slave devices. The seat owner is the compositor input connection, not the actor public key.
- Application: `ApplicationInput` owns the application's master pair and current `controller`. `bind_application()` resolves the real window owner and its existing `ApplicationInput`. It returns `BUSY` if another seat remains its controller. It never cancels that other seat. Worldd first calls `release_input()` for the old actor; that sends the old actor's native cancel operation, whose `cancel(oldSeat)` emits releases and clears the application/controller links. Only the peer's later press can then bind. `bind_application(peerSeat, window)` cancels only the incoming peer seat before assigning it. See `spatialinput.c:278-330` and `actors.cpp:847-948` at source pin `499488301224536e3244989a74896d2b4998231d`.
- Window: `live_window()` checks XID and the private `generation()` value. `invalidate()` cancels a seat targeting or focusing that window before advancing generation. The observer lifetime helper has a separate private window epoch; do not confuse it with the spatial target generation.
- X client and application identity: `SpatialSecuritySameApplication()`, `SpatialSecuritySelectionNamespace()`, and the immutable security connection label bind an X client to workspace/application. `SpatialSecurityInputController()` identifies the compositor input connection. These are not actor cryptographic identities.
- Observer lifetime: `SpatialObserverLifetimeInit/Reset`, `SpatialObserverPinDevices`, `SpatialObserverSnapshotDevices`, `SpatialObserverPinClient`, and `SpatialObserverPinWindow` bind live DIX objects to process-local epochs and a server session. Pinned pointers stay in the server and are not wire inputs. Reset invalidates pins before detaching callbacks.
- Observer capture: `SpatialObserverCaptureArm/Reset` accepts server-local device IDs, recipient index, popup XID, button, and application label. It pins both device sets and the popup, verifies application identity, requires idle replay/frozen state, and checks snapshots. Its event callback sees the actual native-order XI2 event before client byte swapping. It does not authenticate who called arm, or prove delivery.
- Serializer: `SpatialObserverSerialize()` emits Arm and ObserverPress frames from a capture record plus `SpatialObserverTrustedContext`. It accepts supervisor-supplied actor, issuer, arm, session, spatial-generation, watermark, and deadline values. Those values are trusted inputs; the current serializer does not authenticate them.
- Independent probe: the schema's `ProbeReceiptBatch` is a third frame. The separate NativeClient observes actual XI2 events. The supervisor or collector must not synthesize its receipts from server capture.

The current capture helpers are intentionally private. Their headers define no client API, serialized arm capability, socket, or FD writer. Keep transport in its own internal server module; do not add a public X request or alter the application extension policy. Ordinary XACE continues to deny `XInputExtension` to confined applications. The separately authorized NativeClient remains an independent qualification probe outside the application workspace.

PROPOSED TRANSPORT: ONE DEFAULT-OFF INHERITED PIPE CAPABILITY

Use private inherited pipes, not SOCK_SEQPACKET. The accepted collector at `tests/native/input_state_observer_collector.py:14-24,47-60` accepts a nonblocking FIFO or SOCK_STREAM only. Its reader consumes one finite concatenation of canonical varint-length-delimited protobuf records through EOF. A seqpacket envelope is incompatible. A 4096-byte payload plus any envelope can also exceed a 4096-byte packet. Do not add a packet protocol, MAC handshake, or SO_PEERCRED dependency. The trusted supervisor code uses SO_PEERCRED for a distinct control channel (`src/supervisor/host_session_main.cpp:107-115` at pin `499488301224536e3244989a74896d2b4998231d`); this witness does not need it. Linux `man 7 unix`, under `SO_PEERCRED`, says credentials are those effective at `socketpair(2)` time. A parent-created pair inherited by a fork/exec child therefore does not authenticate the post-exec child PID. This design avoids relying on socket peer credentials entirely.

The qualification supervisor is a dedicated test-runner process, added as `tests/native/input_state_observer_supervisor.py`. It creates anonymous pipes before starting the exact pinned `SPATIAL_TEST_XSERVER` binary. Follow the existing launch pattern at `tests/native/test_security_identity.py:103-123`: pass only named descriptors in `Popen(..., pass_fds=...)`, pass their numeric FD values as nonsecret server startup options, and close parent copies not owned by the supervisor. Add default-off X server options `-spatial-observer-control-fd N` and `-spatial-observer-output-fd N` for the arm-control read FD and native-output write FD. They are private process startup configuration. Ordinary X clients get no request, extension opcode, socket path, or FD.

Use four one-way pipes and one collector bridge. The supervisor creates: (1) an arm pipe, write end retained by the trusted supervisor and read end inherited only by Xvfb; (2) a native-output pipe, write end inherited only by Xvfb and read end retained by the supervisor; and (3) a probe-output pipe, write end owned only by the independent NativeClient and read end retained by the supervisor; and (4) a worldd-binding pipe, write end owned by the trusted worldd process and read end retained by the supervisor. The supervisor is the sole coordinator and creates the final collector pipe. The collector takes ownership of its nonblocking read FD on entry and closes it on every exit, as specified by the collector contract. The coordinator owns the final write FD and closes it after forwarding the complete artifact. The X server closes its two FDs on every failure and on reset. Worldd closes its binding writer on every exit. The probe closes its output FD on exit.

The arm pipe carries exactly one bounded, length-delimited `ObserverArmV2` command from the supervisor to the server. The server registers its read end with the pinned X server notify-FD mechanism in the default-off build. Verify that exact API and callback teardown against the corrected XLibre source before implementation. Accept the arm only before old-seat cancellation starts. Reject a second arm, malformed/truncated input, extra commands, stale session, or EOF before the arm. The arm FD itself is the capability: only the trusted supervisor and server possess an endpoint. Mark it close-on-exec after X server startup and close it before any server helper fork. The command is fixed-schema, one-shot, at most 4096 protobuf bytes, with no credentials. It carries actor refs from the trusted worldd context, world actor IDs, seat IDs, app label, XID/spatial generation, arm ID, receipt watermark, and absolute monotonic deadline. The server treats IDs as lookup selectors and independently checks each live native object.

Worldd writes exactly two bounded `ObserverActorSeatBindingV2` records, one per actor, to binding-write after both seats are provisioned. Each record carries one authenticated ActorRef, world actor ID, expected application identity, presentation generation, and native `Seat.id`. The fixture drives the old cancel and peer input through worldd actor sessions. Worldd retains its existing control-lease checks and determines whether the transfer is authorized; the private record never grants or substitutes for that authority. Cap each binding frame at 1024 payload bytes and the two-record stream at 2052 bytes including two-byte prefixes. The supervisor reads binding-read through EOF before it arms; it rejects duplicate actors, missing identities, and extra records. The server writes only its native artifact records to native-write. The NativeClient writes its own `ProbeReceiptBatch` record to probe-write after observing real XI2 delivery. The supervisor reads each producer stream under the same absolute deadline, validates canonical frame boundaries, and concatenates the original artifact record bytes in the required order. It does not create or alter a native or probe record. The supervisor then writes the joined bytes to final-write while `collect_artifact_v2()` drains concurrently from its owned final-read descriptor. A writer loop handles partial writes and EINTR. The M09 collector accepts one absolute `CLOCK_MONOTONIC` deadline in nanoseconds and checks it before and after every wait/read, including EOF; it does not restart the timeout after fragments. Set the deadline immediately before writing ObserverArmV2, and cap the interval at the existing 10-second collector maximum. A stalled producer, early EOF, missing frame, overflow, malformed frame, disconnect, or late EOF fails. Cleanup has a separately bounded allowance.

For protocol v2, allow four artifact records, each at most 4096 payload bytes. The maximum artifact is `4 * (4096 + 2) = 16392` bytes, where two bytes bound the canonical varint prefix at 4096. Keep receipt count at 32. Set the coordinator buffer, producer caps, and v2 collector caps to these same values. Keep the v1 parser and collector contract unchanged: exactly three records and 12294 bytes. Do not stage a locked acceptance or contract update in this planning change.

Ownership at each stage is explicit. Before launch, the supervisor owns all pipe ends. After launch, Xvfb owns only arm-read and native-write. Worldd owns only binding-write. The trusted supervisor owns arm-write, native-read, binding-read, and probe-read. The NativeClient owns only probe-write. During collection, ownership of final-read transfers to `collect_artifact`; final-write remains with the supervisor until EOF. No descriptor is placed in an application environment or workspace. A negative control verifies that a confined application child has none of these descriptors. If any partial spawn or setup fails, close every acquired endpoint and disarm capture.

The trust boundary is the qualification supervisor that creates the pipes and launches the exact server/probe processes. The pipe FD is a capability because no pathname or public X request reaches it. The plan relies on strict FD inheritance, not secrecy of the FD number. The FD number may appear in argv; it grants nothing without the inherited open descriptor. The test supervisor binds the pipe contents to worldd-authenticated actor context described below. If the runner cannot be the parent of the X server, add a private FD handoff in that runner; do not substitute a filesystem socket or broaden XACE.

NATIVE STATE DELTA: VERSIONED TRANSFER EVIDENCE

The current schema at `584ed4e17426a4a8cb9eed1f4ad462bb68d23bbd:spatial-os-luna-handoff/proto/spatial/testing/v1/native_input_observer.proto` has three canonical v1 frames: Arm, ObserverPress, and ProbeReceiptBatch. It proves native down bitmaps and one independently observed peer event. It does not prove complete focus, grab, capture, replay, frozen-state cancellation, or the cancellation transition. Preserve that v1 schema, parser behavior, and locked acceptance unchanged.

Create a separate `spatial.testing.v2` schema and parser contract for the expanded witness. V2 has four canonical records in this order: Arm, NativeTransition, ObserverPress, ProbeReceiptBatch. Its envelope protocol version is 2. Its validator requires exactly these four oneof payloads and exact sequence numbers 1 through 4. Keep a separate v1 decoder path. The v2 artifact cap is 16392 bytes, four 4096-byte payloads plus their two-byte maximum prefixes, and 32 receipts. Update the v2 producer, validator, collector, and new unlocked tests as one reviewed contract change. Do not silently change the current three-frame acceptance or its lock.

`NativeTransition` contains ordered, phase-tagged native snapshots: PRE_CANCEL; POST_RELEASES_BEFORE_CONTEXT_CLEAR; POST_CANCEL; POST_PEER_BIND. These are producer facts, not fixture booleans. The lifetime helper's `SpatialObserverNativeDeviceState` already copies class bitmaps, button state, active grab, native freeze, other-grab freeze, raw sync state, pending-event count, replay-device state, and focus classification. Serialize those values from successful `SpatialObserverSnapshotDevices()` calls on the pinned live devices. Add snapshot completeness/failure reason. Never serialize pointers.

Add spatial input context to each transition snapshot from the actual `SeatRec` and `ApplicationInput`: stable seat ID; current application-controller relation; target and focus XIDs with spatial generations; tracked key/button sets; resolved target owner label; and native device pins. `live_window()` validates XID plus generation. Object epochs from the lifetime helper independently prevent XID/client/device reuse. The worldd mapping described below binds world actor ID and ActorRef to the native seat. Do not treat a device name, XID, PID, or seat integer alone as actor identity.

Capture is distinct from a held button bitmap. The current snapshot records grab existence and freeze state but not grab owner/window. Inspect the exact pinned XLibre grab structure during implementation. Add a bounded capture identity from the actual active native grab and the spatial seat's held-button target/generation. If the pinned server cannot establish capture owner/window without dereferencing a stale object, report incomplete and fail. Do not assert capture clear from zero buttons alone.

`ObserverPress` retains the actual native-order XI2 callback event. The independent NativeClient receipt remains separately produced. `ProbeReceiptBatch` must come from actual XI2 events delivered to that client. The supervisor only joins its exact framed bytes into the final artifact. Require old key/button release receipts in their observed order before the first peer input, and reject duplicate old releases after the peer input. X event time is not the monotonic ordering clock; use producer ordinals and absolute monotonic timestamps.

POSITIVE AND NEGATIVE CONTROLS

Positive ordered timeline: (1) both actors have live worldd ActorRefs and native seats; the old actor has real held key/button state on a mapped application window; (2) before cancellation starts, the trusted supervisor writes one v2 Arm command and the server records PRE_CANCEL; (3) worldd revokes/releases the old actor through its existing `release_input()` path; the native server emits releases through `cancel(oldSeat)`; (4) the server records POST_RELEASES_BEFORE_CONTEXT_CLEAR and POST_CANCEL; (5) worldd authorizes the peer and its first native button press reaches `bind_application(peerSeat, window)`; the server records POST_PEER_BIND; (6) the server callback records the actual peer event; (7) the independent NativeClient records old releases and peer event in its own receipt stream; (8) supervisor joins unchanged server and probe records and closes the collector pipe. The witness passes only if old native key/button/grab/focus/capture/freeze/replay/pending state is clear, peer bindings match, release order precedes peer delivery, and the app process remains alive.

Arm before transfer is required to capture PRE_CANCEL. It is not a negative case. Reject an arm that arrives after cancellation has begun, after POST_CANCEL, after peer bind, or after the peer event. Also reject duplicate arm, wrong application/window generation, stale seat or device, mismatched supervisor/worldd actor binding, wrong world presentation, or a session reset. Keep transport errors distinct from invalid transfer phase.

Other negative controls require their intended rejection: retained old key/button bit; unresolved or stale focus/target generation; active grab; native frozen state or other-grab freeze; pending events; replay state; unresolved active capture; peer event absent from NativeClient receipts; wrong event tuple or synthetic event; duplicate old release after peer delivery; source overflow/disconnect; malformed/truncated/oversize arm or artifact; any frame above 4096 bytes; artifact above 16392 bytes; more than 32 receipts; EOF before all four v2 records; producer silence or EOF only after the absolute deadline; server reset while armed; write/read end leak into an application descendant; and a fresh v1 parser rejecting/accepting a v2 artifact incorrectly. Assert the intended stable reason in every case.
