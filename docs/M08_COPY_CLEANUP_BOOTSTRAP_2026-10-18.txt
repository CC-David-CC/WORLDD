M08 trusted cold-start cleanup binding
Date: 2026-10-18
Status: source increment only; M08 remains UNQUALIFIED.

The supervisor creates a private SOCK_SEQPACKET channel and installs a deferred cleanup participant before starting a supervised workspaced broker. The child sends one canonical state-directory FD with a versioned protobuf frame after ExecutionStore creates execution.db and the schema-8 file journal. It waits for an ACK before set_resources, recovery dispatch, request processing, or readiness.

The bootstrap frame carries only protocol version, correlation ID, and operation kind. The FD and kernel SCM_CREDENTIALS bind the request to the real direct child. The supervisor checks PID and UID, one descriptor, packet framing, configured root path, device, and inode. FileOperationJournal::pin_existing then verifies schema 8 and pins database and filesystem identities. The deferred participant accepts that pin once. Failure prevents readiness and leaves process-stop receipt generation fail-closed.

For production storage-owner launches, configuration validation requires --state-dir to equal the canonical StorageOwner volume root. StorageOwner starts after workspaced exec because StorageClient waits for it; the supervisor receives the bootstrap after StorageOwner startup completes. For the existing supervised fixture lane, the private AuthoritySupervisorConfig supplies one absolute literal --state-dir and the broker resources plus native target. That lane receives the bootstrap without adding --production or changing fixture fault settings.

ProcessScope forks the direct child and execves workspaced in that same PID. The child does not pass through an intermediary executable. Therefore the SCM_CREDENTIALS PID matches ProcessScope::direct_child_pid after exec.
