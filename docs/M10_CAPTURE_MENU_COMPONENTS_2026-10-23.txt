M10 capture transport and menu components
Date: 2026-10-23. Status: IMPLEMENTING, UNQUALIFIED_M10.

The private control schema adds CapturedDeviceEvent, ControlMenuEntry, and ControlMenuView.
These messages carry host input timing and preference UI. They carry no actor tokens, grants, or chosen actor identity.
CapturedDeviceEvent binds each packet to a trusted host capture generation and increasing packet sequence.
DeviceStream owns an inherited unnamed private SOCK_SEQPACKET endpoint with checked kernel peer credentials.
It uses nonblocking bounded packets. A full output queue permanently fences the stream.
Malformed, oversized, stale, descriptor-bearing, and wrong-generation packets also fence it.
The controller still validates every proposed action through ActorControl and worldd.

DeviceAdapters now accepts capture time separately from delivery time.
Mode changes and confirmed cancellation establish a monotonic fresh-input barrier.
Older gestures and samples older than 250 milliseconds cannot renew motion or become calibration input.
Stale release bookkeeping still permits a later fresh press. Active stale input first receives semantic cancellation.
Source heartbeat age uses capture time. Delayed receipt cannot revive a lost source.
The existing direct adapter entrypoint remains for synchronous in-process device translation and fixtures.
Production queued capture must use the timestamped entrypoint.

ControlsMenu implements host preference changes through keyboard interaction.
It supports six presets, sensitivity, inversion, movement style, key rebinding, and independent editable copies.
The measured six-axis wizard rejects missing, stale, ambiguous, and reused raw axes.
Partial calibration is never saved. Cancelling the wizard preserves the previous profile.
Preference-save failure reports that changes apply only to the current session.
The menu controller does not render pixels or own actor authority.
Its compositor rendering and session routing remain pending.
